# Security Policy

## Supported Versions

Security fixes go into the default branch and ship with the next release. Report vulnerabilities against the latest release or the current default branch.

## Reporting a Vulnerability

Report vulnerabilities privately with the **Report a vulnerability** button on the repository's security tab, as [GitHub's guide](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately) describes, not in public issues or pull requests. Include:

- The affected version or commit, and your platform
- Steps to reproduce or a proof of concept
- The impact and any mitigations you know of

The maintainer acknowledges a report within 7 days and shares an assessment within 14 days. For a confirmed vulnerability, the maintainer aims to release a fix within 30 days, coordinates disclosure with the reporter, and publishes the advisory once the fix is released. The repository has a single maintainer, so these are targets, and the advisory thread reports any delay.
